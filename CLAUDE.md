# hyalo: notes for Claude

Spotlight-style launcher for Windows 11, written in Rust. Goals, architecture and roadmap are in `README.md`.

## Working rules

- Follow `/ub-mode` (installed globally) for every code change: failing test first, smallest edit, pure logic, small ordered commits that say why, what changed, and how it was proved.
- Platform glue (Win32, DirectX, COM) stays thin. Anything with a decision in it (layout math, text editing, query parsing, scoring) lives in a pure function with tests. Do not write fake tests for FFI glue.
- Test the glue the way Windows drives it: `test_desktop::on_hidden_desktop` runs a test on a thread attached to a hidden desktop (no flashing windows, no stolen focus); the `Launcher` driver in `window.rs` tests sends real messages (keys, characters, mouse: `click`, `mouse_with` for Shift) and takes stand-in `Services` (sources, file index, icons, places, runner, picks file, hotkeys, tray, config file, autostart keys, position file, Windows' display language, whether Windows hibernates); what Windows answers by posting, such as the `SC_CLOSE` of Alt+F4, happens only once the test pumps the queue (`drain`); tray events go in as `WM_TRAY` messages; file tests walk real trees made with `scratch::Scratch` (under `%TEMP%`, so inside `AppData`: their files carry the AppData penalty, so compare scores with a neighbour's); the files provider serves until nobody but it holds the index, so its tests run it through `Serving`, which drops its `Files` to stop it (a provider closure that keeps a `Files` never ends: hold a `Weak`), and they change the tree on disk and wait for the index to follow; `Renderer::read_frame` reads back the last presented frame so tests can check pixels. Never repaint before reading a frame: the test must see what the code put on screen. Window tests get rates from a stand-in source (`rates::tests::fixture()`, the bank's real answer of 10.11.2026); `http::get` is tested against a `TcpListener` server on 127.0.0.1 inside the test, never against cbr.ru.
- The settings window is tested the same way: the `Settings` driver in `window/settings_window.rs` opens it from the tray stand-in and clicks a control in the middle of where the laid-out page put it (`laid.area(target)`), presses keys with `hold` for the modifiers, and reads back what the page shows and the config file in a `Scratch` folder. The folder picker is the `Picker` service: tests hand it the `Chooser` stand-in, because `picker::System` shows a modal COM dialog; its pieces that need no dialog on screen are tested in `picker.rs`, showing it is checked by hand. A test that waits with `pump_until` must not call `with_app` inside its condition: the condition runs inside one already, and the inner one never borrows.
- Updates are tested the same way: window and settings tests hand `Services.updates` the stand-in `window::tests::releasing` (GitHub's answer, a build and its sum served by URL, an exe in a `Scratch` folder, a starter that only notes what it was asked to start); the swap, the putting back and the tidying run on real files in `Scratch` folders; `update::restart` starts a copy of the test binary, which refuses hyalo's flags and ends. `http::get` and `update::download` meet only a `TcpListener` on 127.0.0.1, never github.com. `Updates::real` is `None` in a debug build, so no test, and no debug hyalo, ever asks GitHub or replaces an exe. The release workflow is pinned by a test that reads it (the asset names, the sum's format); it runs only for a pushed tag, which is the user's to push.
- System commands are never carried out by a test, nor by hand during a live check: the user's machine must stay up and their bin full. Window tests see them reach the stand-in runner (`Action::System`); `system::run` takes a `Windows` and its test hands it `Noted`, which only notes the call; `system::System`, the real one, is one Windows call per method and checked by reading it.
- A test that touches the clipboard runs through `test_desktop::in_own_window_station`, in a child process with a window station of its own: the hidden desktop shares the user's clipboard, and a test must never overwrite what the user copied. The hidden desktop and the launcher work there too (Ctrl+V is tested so); DWM refuses the settings window's Mica there, so that window opens plain. The child's output is shown only when it fails. Since the evening of 10.11.2026 Claude's shells run with a token that has no logon SID, and the window station the children share (`Service-0x0-<logon session>$`, held by another process of the session) gives that SID its rights: the four clipboard tests fail there with 0x80070005, whatever the code. An instrumented test run in which any test fails writes an empty profile, so `scripts/gates.sh crap` then scores every launcher function at 0 %: make the launcher's coverage in `crates/hyalo` with `cargo llvm-cov --lcov --output-path <repo>/target/coverage/rust/crates__hyalo/lcov.info -- --skip <each of the four tests' full names>`, the other crates' the same way without the skips, then run `scripts/gates.sh crap --use-existing-coverage crates`.
- A test about how the process ends runs through `test_desktop::exit_code_on_hidden_desktop`: a child process runs it on the hidden desktop, then exits from that thread, as hyalo does when `main` returns, and the test reads the exit code. A test thread that just ends cleans up while the rest of the process runs, so only an exit shows what is left for the exit to release.
- A test that waits for the shell to list apps or draw icons does it through `apps::tests::shell`: COM on a thread of its own, given a minute by `test_desktop::within`, after which the test fails and the stuck thread is left to end with the process. Under eight full suites at once the shell once never answered, and the mutator's warm-up, which runs every worker's suite untimed, sat for 1.5 h. Production needs no deadline: the window never waits for a provider, and a stuck one costs only its thread.
- The hidden desktop shares more with the user's than the clipboard. Global hotkeys are the whole session's: one held on the user's desktop is refused on the hidden one and the other way round, so window tests register through the `Keyboard` stand-in (`hotkeys::Hotkeys`), and only `hotkeys::System`'s own test registers a real one (`Ctrl+Alt+Shift+Win+F24`, for a moment). The hidden desktop has no taskbar, so `Shell_NotifyIcon` fails there: window tests use the `Taskbar` stand-in (`tray::Tray`), which also picks the menu's entry. Registry tests use keys of their own under `HKCU\Software\hyalo-test-<pid>-<test>` (`autostart::tests::Keys`, deleted on drop), never the real Run key. A launcher given a config path writes the default config there when it is missing: give tests a path inside a `Scratch` folder, never one outside it (a test once left `C:\nowhere\hyalo` behind).
- Drawing is pinned by reference images (`crates/hyalo/reference`, compared by `reference::assert_looks_like`). Change the look on purpose, look at the new frames, then accept them with `HYALO_BLESS=1 cargo test -p hyalo`. Never bless a frame you have not looked at. The PNGs hold premultiplied colour, which a viewer shows too dark: `scripts/frames.ps1 -Files a.png,b.png` writes each over a dark backdrop to `target/look/<name>-over.png` for looking.
- Before a commit: `cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, `scripts/gates.sh`.
- Mutation testing on changed code: `scripts/gates.sh mutate --changed` (it reads `git status`: once committed, name the files instead). Goal: no survivors, no uncovered sites. Stock mutator fails on Windows; `~/code/unclebob/mutator` is on the `windows-support` branch, which fixes it. Do not run heavy builds while mutator runs: a mutant that times out counts as killed. For the launcher crate pass `--max-workers 8`: 24 workers linking at once have failed with LNK1201. A launcher run takes most of an hour: send its output to a log, and wait for its last line (its exit) before reading the results or starting anything else. A wait that timed out once looked like the end, a second run started beside the first, and the first's results came out wrong (a whole file "uncovered"); only a clean `--mutate-all` run alone could be trusted. Where Windows refuses symlinks, a worker is a copy of the project root: the local mutator leaves `.claude` out of it since a run copied other sessions' worktrees (their own running workers too) into each worker and filled the disk. While the clipboard tests cannot pass in this shell (below), run the launcher's mutation with the coverage made as below, `--use-existing-coverage`, and `--test-command "cargo test -p hyalo -- --skip <each of the four>"`.
- Gate thresholds follow ub-mode: every function under CRAP 10, no duplicate candidates at similarity 0.8 or above.
- Check UI changes with your own eyes: run `target/debug/hyalo.exe`, then `powershell -ExecutionPolicy Bypass -File scripts/snap.ps1 -Stripes` (add `-Type "no{DOWN}"` to see the list, `-Settings` for the settings window) and read `target/snap.png`. On a dark desktop the glass looks solid; the stripes show whether it really blurs. snap.ps1 shows the launcher with a second start of `hyalo.exe` (it asks the running one to show, whatever the hotkey) and types with `SendMessageW` (`WM_CHAR`, and `WM_KEYDOWN` for `{DOWN}` and the like), so the keys reach the launcher whatever has the focus. A process started from a background shell may not take the foreground, so the settings window would open behind other windows: `-Settings` first presses the hotkey config.toml names (once it has checked that someone holds it, so the keys reach no other app), which hands hyalo the foreground as a real key press does. A PowerShell script with Cyrillic in it needs a UTF-8 BOM. New tray icons start in the overflow behind `^`. The Store Notepad restores the user's tabs when it starts; leave its windows alone.
- The user runs hyalo every day: a release build in `%LOCALAPPDATA%\Programs\hyalo\hyalo.exe`, started with `--hidden`, on their own `%APPDATA%\hyalo\config.toml` (hotkey F4). Because of the single instance, a debug `hyalo.exe` started while theirs runs only asks theirs to show. Before a live check: back up `config.toml` (and `frecency.json`) with their hashes, then stop their copy (tray Exit, or `taskkill /IM hyalo.exe`; a debug build, a console app, ignores a plain `taskkill`: post `WM_CLOSE` to its `hyalo.launcher` window). Afterwards: put the files back byte for byte and check the hashes, start theirs again (`"%LOCALAPPDATA%\Programs\hyalo\hyalo.exe" --hidden`), and check it holds F4 (a `RegisterHotKey` for F4 from another process must fail). Never overwrite that exe: the updates step owns it.
- The user may be at the keyboard during a live check: they once recorded F4 back in the open settings window while a check had moved hyalo to F19. Drive hyalo with posted messages (clicks at a control's place, `WM_KEYDOWN` with no modifier), never the real mouse; send real key presses only right after checking the target window is in front, and prefer a key no app uses (F13 to F24) when a hotkey must be registered for real. Put the settings window on top for a capture with `SetWindowPos(HWND_TOPMOST)` and no activation, then back, rather than taking the focus. In the real folder picker the folder box is the `Edit` with control id 1152 on the dialog itself (the one in the address bar is hidden and ignored), and Select Folder takes a `BM_CLICK` on control 1, not a `WM_COMMAND`. Capture with `-Margin 0` and delete any capture that shows another app's window.
- Cargo is in `~/.cargo/bin`; a fresh shell may need `export PATH="$HOME/.cargo/bin:$PATH"`.
- The repository uses LF. Python in text mode on Windows writes CRLF: open files with `newline='\n'`. Shell heredocs here may eat a backslash (`'\\'` came out as `'\'`); edit Rust with backslashes through the editor tool.
- Search speed: `cargo bench -p hyalo-index` (a million synthetic names; `HYALO_BENCH_NAMES` for more). Keep every query under 20 ms in release.

## Windows specifics

- Target Windows 11 (22H2+) for the DWM system backdrop. Older systems get a solid background.
- The launcher process must never run elevated: launched apps would inherit elevation and drag-and-drop to normal windows breaks.
- Use the `windows` crate for Win32 and COM. Keep each `unsafe` block small, with a comment stating the invariant it relies on.
- Release Direct3D before the process exits. The thread-locals of the thread that ends the process (the UI thread, when `main` returns) are dropped only as it exits, after Windows has stopped every other thread, and releasing a D3D11 device there ends the process with 0x87A instead of 0. So the launcher's `App` (its renderer with it) goes at `WM_DESTROY`.

## Glossary

- **Launcher**: the UI process, `hyalo.exe`.
- **Indexer**: the Windows service that will hold the file index (a later step). Until then the launcher holds it.
- **Index**: every file and folder name the launcher can find (`hyalo-index`): names in one arena, folded names in another, one 16-byte **entry** per file or folder (its folder, where its names are, flags), and beside it its place in its folder's list of entries, so a path is found and a folder removed without a pass over the index. Changed only by add (a walk's, into a folder it has not seen), put (an add that looks first, so it may run twice), remove (with everything under it) and rename (replacing what had that name), so a walk, a watch or the NTFS journal can drive it. Names given up are reclaimed once they are half the arena.
- **Root**: an entry with no folder, such as `C:`; holds entries but is never a result.
- **Walk**: the files provider reading the fixed drives folder by folder with the user's rights. Lists junctions and symbolic links, never enters them.
- **Watch**: a root followed with `ReadDirectoryChangesExW` (the whole tree, names, with attributes) on a thread of its own, set before the walk starts so nothing is missed. Its **records** (added, removed, modified, old name, new name, with full paths) become changes (`files::changes`): an old name and the new one after it are one move; a move to another folder comes as removed and added. A change goes by the walk's rules; a folder that comes whole is walked afresh, after checking on disk that it is no junction (`mklink /J` tells of a plain folder first). One that falls behind, or opens its root again, says `Lost`, and that root alone is walked again into an index of its own, then put in place of the old (`Index::replace`). The provider tells the window at most twice a second, and only when the index's version moved.
- **Snapshot**: the index on disk (`%LOCALAPPDATA%\hyalo\files.idx`), checked where it is read; the folded names and the folders' lists are made again on load. Saved after each walk, at most every six hours while the index changes (something always does: browsers' caches, the snapshot itself), and when the provider ends.
- **Ceiling**: the most points a name could score, read cheaply from its folded text (rough) and its word starts; the search scores in full only names whose ceiling beats the rows already kept.
- **Filter**: `ext:`, `in:`, `size:` or `mod:` among a query's words (`hyalo_core::filter`: `Query::parse(text, Clock)` gives the words and `Filters`; `Clock` is now and how far local time is ahead of UTC, from `GetTimeZoneInformation`). Filters narrow files and folders alone: apps match the words, the answer reads the whole text, picked files must pass the index's `Sieve`. The index checks an entry's kind, extension (folded), size, time and folders (`in:` resolved to folder entries once per search) before its name; filters alone list by kind and place, the newest first (`Results::filtered` lifts picked ones by frecency for the text as typed). A value that does not read stays a word.
- **Stat**: a file's size and last write, kept beside each entry (u64 bytes, u32 seconds since 1970) and in the snapshot; the walk reads it with the name, a watch's records carry it (sizes and times are watched too: a write is `Modified`, a `Touched` change).
- **Places**: where a file lives, in points: favoured folders (Desktop, Documents, Downloads, projects) +3, buried ones (`node_modules`, `AppData`, caches, `Windows`, any name starting with a dot) −10.
- **Provider**: a source of results (apps, files, calculator, settings, windows). Runs off the UI thread and hands what it finds to the window piece by piece.
- **Catalog**: what the launcher can search right now: the items providers found, and their icons.
- **Item**: one row in the list (a "result" in the UI): id, title, subtitle, keywords, kind (app, file, folder, calculator, setting, command, web, window, notice), the action Enter runs. Named `Item` so it does not clash with `std::result::Result`.
- **Keywords**: an item's other names, never shown: a Windows setting's name in the other language and words people search it by. Ranking takes the best of the title and the keywords; a keyword match is worth two points less and highlights nothing.
- **System setting**: a page of Windows' Settings app (`ms-settings:`) or a Control Panel item, from the table in `hyalo_core::system_settings` (names in English and Russian, keywords, what opens it, which shell item's icon it shows). Its row is titled in hyalo's language and says where it lives; `Kind::Setting` ranks at the apps' step. Icons come from `catalog::find_system_icons`: the Settings app's gear for every page, each Control Panel item's own `shell:::{CLSID}`.
- **System command**: Lock, Sleep, Hibernate (listed only when Windows hibernates), Restart, Shut down, Sign out, Empty Recycle Bin (`hyalo_core::system_commands`, `Action::System`); drawn with a symbol of Segoe Fluent Icons (`results::glyph`); carried out by `system::run` through the `Windows` seam.
- **Asking**: what a row whose command asks first (all but Lock) does at the first Enter: its second line asks to press Enter again, in amber, and the next Enter runs it. Any other key, typing, a click off the row, another row selected or hiding stops it; a refresh keeps it for the same item. Pure, in `Results` (`confirm`, `calm`, `subtitle`); which actions ask is `Action::asking`.
- **Pick**: choosing an item with Enter. Frecency counts picks per item and query.
- **Frecency**: a score from how often and how recently an item was picked for a query; a pick also counts, scaled down, while its query is still being typed. Halves every two weeks.
- **Match strength**: how a query fits a name, strongest first: exact, prefix, word start, acronym (starts of words, in order: `vsc`, `vscode`), substring. Letters compare case-insensitively, with `ё` as `е`.
- **Wrong layout**: a query typed with the other keyboard layout active (`мысщву` for `vscode`). It still matches, a little weaker.
- **Answer**: the row listed first, above the usual results: a web search, else the calculator's, else a currency conversion. A query with an operator or a function that reads as one whole expression gets the calculator's; Enter copies it. A bare number gets none, so it still just searches. A query the calculator does not answer that is an amount and a currency (`100 usd`, `10$ в евро`) gets a conversion at the rates instead.
- **Web search**: a query of a prefix, a space and words (`g rust lifetimes`) gets a row that searches an **engine** for the words; Enter opens the browser at the engine's address with `{query}` replaced by the words percent-encoded (`hyalo_core::web`). Engines are built in (`g`, `gh`, `yt`, `w`, `ya`) or the config's (`[search]`, `prefix = "address"`), which come first, so one can take a built-in prefix over. A prefix alone, or a word that only starts like one (`git`), is no web search. Not a pick.
- **Window switcher**: a query starting with `>` lists the open windows instead of the usual results, filtered by the rest (`hyalo_core::switcher`): the title, or a little weaker the app's name. Which windows count is the Alt+Tab rule (`switchable`); the windows provider reads them front first (`switcher.rs`), on every show, and Enter switches at once on the UI thread (`launch::at_once`), before the launcher hides and gives the foreground away. A window is never a pick.
- **Rates**: the Bank of Russia's official exchange rates of one day: roubles per unit of each currency it publishes, from its daily XML (`XML_daily.asp`). Kept as the bank sent them in `%LOCALAPPDATA%\hyalo\rates.xml`; asked for again when older than today in Moscow, once a day when the bank has nothing newer.
- **Backdrop**: the blurred glass behind the window, drawn by DWM.
- **Reference image**: a PNG of a frame someone checked by eye; rendering tests compare fresh frames with it.
- **Config**: the user's settings in `%APPDATA%\hyalo\config.toml` (`hyalo_core::config` reads the text, `settings` moves it): the hotkey, the language, the folders to exclude and to rank lower or higher, and the web searches of the user's own (`[search]`). Written with the defaults when missing, watched while the launcher runs; a good save is put in force at once, a broken one keeps the last good settings (at start, the defaults) and becomes a notice.
- **Hotkey**: modifiers and one key that show and hide the launcher, named as the config writes it (`Ctrl+Shift+K`). Registered with Windows, which may refuse one another app holds; a refused hotkey leaves the one in force.
- **Language**: what hyalo says things in, English or Russian (`hyalo_core::text::Language`): the config's `language` ("en", "ru"), or, when it names none, the language Windows is shown in (`GetUserDefaultUILanguage`, read at start into `Services.windows_language`). A config written the first time names the Windows one. Everything hyalo shows comes from one **Text** table, written by a macro that wants each sentence in both languages, so a missing translation does not compile; words go in a sentence's `{0}`, `{1}`. Names stay as they are: hyalo, config.toml, keys, files, apps; TOML's own error messages stay English. Errors are kinds (`hotkey::Wrong`, `config::Why`) said in a language when shown; their `Display` is English, for logs.
- **Notice**: what hyalo tells the user, quietly: a row under the empty search bar (never while typing) and the tray's tooltip; Enter on it opens the settings window, which shows the problem. A problem in the config, or a hotkey Windows refused.
- **Tray**: hyalo's icon in the notification area and its menu (Show hyalo, Settings, which opens the settings window, Start with Windows, Exit), built from a list of lines. Added again when Explorer restarts (`TaskbarCreated`).
- **Excluded**: full paths the config leaves out of the index with everything under them. The walk never lists them, nor a watch's changes; the files provider takes them out of the live index before and after its walk, after each batch of changes, and as the config changes; one no longer excluded is put back and walked.
- **Autostart**: the `hyalo` value in the current user's Run key, naming the exe with `--hidden`; Windows' own switch under `StartupApproved\Run` can turn it off. Off by default; a debug build never offers it.
- **Single instance**: the mutex `Local\hyalo.launcher`; a second start finds it held, asks the running launcher to show (`WM_SHOW`), or with `--settings` to open its settings window (`WM_SETTINGS`), and ends. A first start goes through the same messages, posted to itself.
- **Settings window**: the window that changes the config (`window/settings_window.rs`): a top-level window with a title bar and a taskbar button, dark over Mica (the backdrop for windows that stay open; the launcher's Acrylic is for windows that come and go). One at a time; the tray's Settings, Enter on a notice and `--settings` open it or bring it forward; Esc closes it. Every change is written to config.toml at once, and the watcher puts it in force, as it does an edit saved in a text editor.
- **Written**: the settings as config.toml writes them (`config::written`): the hotkey and each list's entries as typed, not folded as `Place` keeps them; a web search is listed as `prefix address` (`List::Search`), the entry the settings window shows and adds. What the settings window shows.
- **Edit**: one change made in config.toml's text (`config::edit`, with `toml_edit`): only the value that changed, in the text on disk at that moment; comments, order and layout stay. A broken file is refused (`Refusal::Broken`), so is a change that would break it (`Refusal::Wrong`). Written whole through a temporary file.
- **Panel**: the settings window's state apart from Win32 (`panel.rs`): what the file writes, the recorder, the name fields, the focus (ringed when it came from the keyboard), the pointer and the scroll; it speaks the file's language, or Windows'. It turns input into an **Effect** for the window to carry out: a change to write, the folder picker, the Run key, the file to open, text to copy, the clipboard to paste, closing.
- **Page**: what the settings window shows: a title, then sections of cards built from a list (`panel::SECTIONS`; the updates step adds one), each card a stack of strips (a setting with its control, an entry with its ×, a field with its Add, a paragraph). `page::lay_out` places every piece in DIPs; drawing (`paint.rs`), what is under the pointer and Tab order all come from that one layout.
- **Field**: a line of text being edited (`field.rs`): the launcher's query and the settings window's name fields. Text, caret and the selection's anchor in `char`s (`utf16_offset`/`char_index` for DirectWrite). `field::key` says what a key does (move, select with Shift, by word with Ctrl, erase, select all, copy, cut, paste); a click places the caret (`HitTestPoint`), a drag selects, a double-click selects a word, a third click all. A field wider than its view scrolls to keep the caret in sight (`field::scrolled`). In the launcher, Ctrl+C copies the selected text, or with none the selected row's path.
- **Part**: what a point of the launcher is on (`layout::part_at`): the query's **Text**, a **Row**, or the **Glass** around them (the search icon, the room right of the query, the list's padding, the edges), which is where the launcher is dragged.
- **Position**: where the user dragged the launcher (`layout::Position`): its centre's offset from its work area's centre and its top's offset from the work area's top, in DIPs, kept within the work area with the longest list; in `%LOCALAPPDATA%\hyalo\position.txt`, not the config. A double-click on the glass forgets it. The window moves itself with the mouse captured; `WM_NCHITTEST` stays `HTCLIENT` (Windows' own move would snap and maximize).
- **Release**: a GitHub release of hyalo, tagged `v<version>` and carrying `hyalo.exe` and `hyalo.exe.sha256` (`hyalo_core::update::Release`); published by `.github/workflows/release.yml` for a pushed tag that names the workspace version. **Version**: three numbers, the workspace's for the build that runs (`update::current`).
- **Check**: asking GitHub for the latest release (`releases/latest`), at start and when the launcher shows, at most once a day, an hour after a failure (`Checked::due`); `check_for_updates = false` in the config stops it. A debug build never checks.
- **Update**: a release newer than the build that runs, and how far installing it came (`Progress`: offered, installing, failed with a `Failure`). Told by the notice, the tray's Install line and the settings window's Updates section, which comes first on the page while there is one.
- **Install**: downloading the release's sum and exe, refusing an exe its SHA-256 does not name, the **swap** (`hyalo.exe` renamed to `hyalo.exe.old`, the new one in its place; a running exe can be renamed, not overwritten), and starting the new build with `--hidden --replace`; this launcher then closes. **Handover**: a start with `--replace` waits for the launcher's mutex (`Taken::wait`) and runs once the old process ended; it then tidies `hyalo.exe.old` away, or, when its window cannot open, puts the old exe back (its own goes to `hyalo.exe.failed`) and starts that one the same way.
- **Recorder**: the hotkey field: once clicked, it takes the next combination pressed (`Hotkey::from_keys`), registers it first and writes it only if Windows took it; Esc keeps the one there is, and Alt+F4 alone closes the window rather than become a hotkey that takes Alt+F4 from every window. The hotkey itself reaches hyalo as `WM_HOTKEY`, not as keys: while the recorder listens, that is the hotkey there is, and nothing changes.
